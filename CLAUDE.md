# Apeiroq.com

Marketing site for **Apeiroq** — an IT company selling custom software engineering to international clients. Tagline: **Scale Beyond Limits**. Fully remote team of 12 engineers, bootstrapped, 3 clients, 3–4 in-house prototypes.

The site's job is to make a serious international buyer trust a small unknown team enough to start a conversation. Every technical decision serves that.

**[DESIGN.md](DESIGN.md) is the authoritative design spec** — brand, color, type, motion, UI patterns, page architecture, performance budget. Read the relevant section before building any UI. Do not invent design decisions that file already makes; if it's silent, follow its principles rather than defaulting to generic patterns.

## Rule zero: this is not the Next.js in your training data

Per AGENTS.md: **read the relevant guide in `node_modules/next/dist/docs/` before writing code.** Especially `01-app/01-getting-started/` and `01-app/03-api-reference/`. The following are verified from those docs and are the ones most likely to trip you up.

### Async request APIs — synchronous access is fully removed

`cookies()`, `headers()`, `draftMode()`, `params`, and `searchParams` are **async only**. The v15 sync compatibility shim is gone.

```tsx
// app/blog/[slug]/page.tsx
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params
  // ...
}
```

`PageProps`, `LayoutProps`, and `RouteContext` are globally available type helpers generated by `next typegen`. Use them instead of hand-writing `{ params: Promise<{ slug: string }> }`.

Also now promises: `params` **and** `id` in `opengraph-image`, `twitter-image`, `icon`, `apple-icon`; `id` in the `sitemap` function when using `generateSitemaps`. (`generateImageMetadata` still receives sync `params`.)

### Other v16 changes that matter here

- **`middleware.ts` → `proxy.ts`**, exporting `proxy()`. Node runtime only, not configurable. We should not need one — if you reach for it, reconsider.
- **`revalidateTag` requires a second argument** (a `cacheLife` profile): `revalidateTag('posts', 'max')`. Single-arg is deprecated and errors in TS. For read-your-writes in a Server Action, use `updateTag(tag)` instead.
- **`cacheLife` / `cacheTag` are stable** — import from `next/cache` without the `unstable_` prefix.
- **PPR**: the `experimental.ppr` flag and `experimental_ppr` segment config are removed. Opt in via `cacheComponents: true` if ever needed. Not enabled here — a fully static marketing site doesn't need it.
- **`next/image` defaults changed**: `qualities` now `[75]` only (a `quality` prop outside the array is coerced to the nearest allowed value), `minimumCacheTTL` is 4h, `16` removed from `imageSizes`, redirects capped at 3, local IP optimization blocked. `images.domains` and `next/legacy/image` are deprecated — use `remotePatterns` and `next/image`.
- **Turbopack config is top-level** `turbopack: {}` in `next.config.ts`, no longer under `experimental`. Adding a custom `webpack` config will **fail the build**.

## Architecture

```text
app/
  layout.tsx              root: Sora, metadataBase, title.template, JSON-LD (Organization + WebSite)
  page.tsx                Home
  globals.css             @import "tailwindcss" + @theme tokens
  sitemap.ts              MetadataRoute.Sitemap — all static routes + all blog posts
  robots.ts               MetadataRoute.Robots
  opengraph-image.tsx     default OG card (ImageResponse from next/og)
  about/ projects/ blog/ careers/ contact/ hire-us/
  actions/                Server Actions (newsletter, contact)
components/
  ui/                     primitives (Button, Container, Section, Arrow, Logo)
  layout/                 chrome (Header, MobileMenu, Footer)
  sections/               composed page sections (Hero, PageHero, NewsletterForm, ...)
  reactbits/              vendored React Bits components — see below
lib/                      site config, schema.org builders, utils
content/                  MDX blog posts, projects, roles, testimonials, media-credits.md
public/logos/             brand artwork — see DESIGN.md §6 (Logo)
public/media/             optimized video + posters
```

`lib/site.ts` is the single source of truth for site constants and navigation. Anything unconfirmed there is marked `TODO` and wired so it renders nothing rather than something false.

Sections are composed in pages; primitives never import from `sections/`.

### Server Components by default

`"use client"` is a last resort, pushed to the smallest possible leaf. **A `page.tsx` or `layout.tsx` is never a client component.** If a section needs one interactive bit, extract that bit — don't mark the section.

Legitimate client boundaries here: mobile menu, sticky-header state, disclosure cards, scroll-snap rail controls, background video mount, newsletter/contact form state, scroll-reveal wrapper. That's roughly the whole list.

Form submissions go through **Server Actions**, validated server-side. API keys never reach the client.

### Content

Blog posts, projects, roles, and testimonials are filesystem content in `content/`, read at build time. Every route statically prerendered. Nothing opts into dynamic rendering without a written reason in the PR.

## Styling

Tailwind v4 is CSS-first — **there is no `tailwind.config.js`, do not create one.** Tokens live in `@theme` in `app/globals.css`; see DESIGN.md §4 for the exact block.

- **Never hardcode a hex, font size, or spacing value** in a component. If a token doesn't exist, add it to `@theme` — after checking DESIGN.md, which probably already names it.
- Tailwind utilities for everything. CSS Modules only when a utility genuinely can't express it (complex keyframes, `::selection`). No CSS-in-JS.
- **Cascade layers bite.** Tailwind's `utilities` layer outranks `@layer components` regardless of specificity, so a components-layer rule can never override a utility class on the same element. Global CSS that must beat a component's own utilities (the header overlay rules) is written **outside `@layer` on purpose** — unlayered CSS outranks every layer. Do not "tidy" those blocks into a layer; it silently breaks them.

### React Bits

Components are copied into the repo via the shadcn CLI — once added they are **our code**, to edit and simplify:

```bash
npx shadcn@latest add @react-bits/<ComponentName>-TS-TW
```

Always the **`-TS-TW`** variant (TypeScript + Tailwind); the JS and plain-CSS variants don't belong in this codebase. Confirm the exact component name on reactbits.dev first — names are case-sensitive and the catalog changes.

Land them in `components/reactbits/<Name>.tsx` with a header comment recording source URL, variant, and date. Then delete every prop and branch we don't use.

**Limits (DESIGN.md §7):** max 3 React Bits components per page, max 1 WebGL/canvas component per page and never above the fold, `dynamic(..., { ssr: false })` + mount on intersection for anything canvas-based. Any component dragging in a heavy runtime (GSAP, three, ogl, motion) must be lazy-loaded and measured against the JS budget **before** merge. Prefer a CSS reimplementation when one is plausible — most of the UI patterns in DESIGN.md §2 are pure CSS by design.

## Non-negotiables

### Performance — target is 100/100/100/100 mobile

Full budget in DESIGN.md §9. The gates:

- Initial JS **< 120KB gzipped per route**; LCP < 1.8s; **CLS exactly 0**; TBT < 150ms.
- **Zero third-party scripts at first load.** Analytics via `next/script` with `strategy="lazyOnload"`. No chat widget, no tag manager, no CAPTCHA.
- `next/image` always (never a raw `<img>`), always with dimensions or `fill` + a sized parent. One `priority` image per page, above the fold.
- `next/link` for every internal link.
- Background video never becomes the LCP: the poster image is the LCP element, the video mounts post-paint on idle, and is skipped entirely under 768px, on save-data/2G, or with reduced-motion. Encoding budget ≤1.8MB, ≤12s, no audio track — ffmpeg recipe in DESIGN.md §8.
- Measure on `npm run build && npm start`. Dev-server numbers are meaningless.

### Accessibility

Semantic landmarks, one `<h1>`, no skipped heading levels, skip-to-content link, visible `:focus-visible` ring everywhere (never `outline: none` without a replacement), labelled inputs, text-not-color error states, `aria-hidden` on decorative media, full keyboard operability including focus-trapped mobile menu. `prefers-reduced-motion: reduce` must disable video, canvas, and transitions — that's a functional requirement, not a nicety.

### SEO — every route

Unique `title` (≤60 chars) and `description` (140–160), `alternates.canonical`, and an OG image. Root layout owns `metadataBase` and `title.template`. JSON-LD per DESIGN.md §10: `Organization` + `WebSite` at root, `BreadcrumbList` on nested routes, `BlogPosting` on posts, `JobPosting` on roles, `Service` on `/hire-us`.

Never emit `Review` or `AggregateRating` markup without verifiable attributed reviews.

### Content integrity

**Never write a number, client, logo, testimonial, award, or review that isn't real.** No "500+ projects", no placeholder logo walls, no invented metrics — not even as temporary filler, because filler ships. If real content is missing, use a clearly-marked `TODO:` and tell the user what's needed. We have 3 clients and 3–4 prototypes; the design (DESIGN.md §1) is built to make that read as focus rather than absence.

Copy follows the voice rules in DESIGN.md §1: declarative, specific, unpadded. No "leverage", "cutting-edge", "passionate about", no exclamation marks.
